# 常见问题

## 隧道相关

### 隧道点了连接就断开 / cloudflared 启动即退出

按顺序排查：

1. **凭据对不对**：「系统配置」里重填 Account ID + API Token，点「测试配置」确认通过
2. **云端隧道还在不在**：如果这个隧道在 Cloudflare 后台被删过，本地记录就是空壳，删掉重建一条
3. **协议问题**：有些网络屏蔽 UDP，把「连接参数 → 协议」从 `QUIC` 改成 `HTTP2`
4. **看日志**：「运行日志」页会**把真正的错误行提取置顶**，先看那一行

### 面板显示「云端在线，本地离线」

这说明 Cloudflare 云端认为隧道活跃，但**你这台机器上并没有对应进程在跑**——通常是：

- 面板刚重启，隧道还没自动连上（等几秒或点一下「连接」）
- 之前连接过又手动断开了
- 这条隧道实际跑在**另一台设备**上（筛选条里会标 🏠 本机 / ☁️ 其他设备）

以「本地」状态为准——只有本地进程真的在跑、并且日志出现 `Registered tunnel connection` 才是真的通了。

### 同一条隧道能同时连多次吗？

不要。同一条隧道在多个地方跑会导致边缘连接来回抖动。多条**不同**隧道同时在线才是这个项目支持的场景。

## 域名与 DNS

### 自定义域名能用 HTTPS 吗？

能。添加转发规则时面板会自动创建 **CNAME 记录并开启橙云代理**（proxied）。此时：

- 访问 `https://你的域名` 由 Cloudflare 边缘直接提供证书，**不用自己申请**
- 你的真实出口 IP 被隐藏

### 同一个内网服务能同时挂「随机域名」和「自定义域名」吗？

可以。在隧道的路由规则里加**两条规则**指向同一个内网服务即可，例如：

```text
abc123xyz.example.com   →  http://192.168.1.10:5000
nas.example.com         →  http://192.168.1.10:5000
```

调试期常用这个做法：先用随机域名验证通了，再换正式域名。

### 删除隧道会删掉 DNS 记录吗？

不会自动清理。删隧道只删云端隧道和本地记录，之前创建的 CNAME 会留在你的 DNS 里——需要的话去 Cloudflare 后台手动删。

### 普通用户点「🎲」提示「请先设置默认域名」

默认域名是**管理员在「系统配置 → 默认域名」里设置一次**的，普通用户会继承这个设置。出现这个提示说明管理员还没设，或者刚设置完页面还没刷新（刷新一下即可）。

## 更新相关

### `git fetch` 报 `HTTP/2 stream 1 was not closed cleanly`

国内直连 GitHub 的经典故障，与你的配置无关。用带镜像的命令更新：

```bash
git -c http.version=HTTP/1.1 fetch https://v4.gh-proxy.org/https://github.com/lieren2012/cloudflare-tunnel-manager.git main && git reset --hard FETCH_HEAD
```

或者直接 `bash update.sh`，脚本会自动切换可用镜像。

### 更新完版本号没变

1. **Ctrl + F5** 强制刷新浏览器（前端有缓存）
2. 确认容器真的重建了：`docker compose ps` 看启动时间
3. 确认代码真的拉下来了：`git log --oneline -1`
4. 浏览器里看的是不是另一个端口 / 另一个容器的实例

### 拉取基础镜像很慢

项目默认走 `docker.1ms.run`。如果你的网络环境它也不快，在项目目录 `cp .env.example .env` 后改成别的加速站或官方源：

```ini
NODE_IMAGE=node:22-alpine
CLOUDFLARED_IMAGE=cloudflare/cloudflared:latest
```

### 面板内「更新到最新版」按钮点不了

**第一次**必须用命令行更新一次（旧容器没有源码挂载、没有新版镜像）。之后按钮就能一直用了。详见 **[更新与国内加速](/guide/update)**。

## 账户相关

### 忘记管理员密码了

给容器加环境变量 `ADMIN_PASSWORD`：

```yaml
environment:
  - ADMIN_PASSWORD=你的临时密码
```

然后登录页**用户名填 `master`（或留空）**、密码填这个值。进去后在「用户管理」里重置正式密码。

### 新注册的用户登录不了

需要管理员在「用户管理」里**点「通过」审核**才能登录。这是防止陌生人注册的默认机制。

### 能用多个人的账号管理各自的隧道吗？

能。第一个注册者是管理员，之后每个用户注册并经审核后，**只能看到和管理自己创建的隧道**；管理员看全部。

## 部署相关

### 19090 端口被占用

改 `docker-compose.yml` 或 `.env` 里的端口映射，或者直接改 `WEB_PORT` 环境变量。

### 能不能不用 Docker

可以，但需要本机已装 `cloudflared`：

```bash
npm install && npm start
```

（面板内一键更新依赖 git 工作区和源码目录，非 Docker 方式同样可用。）

### 项目会把我 NAS 上的信息传到哪吗？

不会。所有凭据、用户、隧道配置都只存在你自己的 `data/` 目录，项目不含任何上报或统计逻辑。项目与 Cloudflare, Inc. 无关，非官方项目。

## 还没解决？

去 [GitHub Issues](https://github.com/lieren2012/cloudflare-tunnel-manager/issues) 提问，附上：版本号（关于页可见）、你的操作步骤、以及**运行日志里置顶的那几行错误**。

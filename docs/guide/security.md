# 安全与公网暴露

这个面板能创建隧道和 DNS 记录，**等于你内网的入口**。它默认面向内网使用，放到公网前请按本文做一遍。

## 默认状态与风险

下表以 Docker 默认部署为准。桌面 v1.8.1 只监听本机 `127.0.0.1`，端口动态选择。详见 [桌面数据与端口](/guide/desktop#端口和数据目录)。

| 项目 | 默认 | 风险 |
|---|---|---|
| 面板登录 | **首次启动引导注册管理员**，之后需登录 | 未设 `ADMIN_PASSWORD` 时紧急通道关闭，属正常 |
| 开放注册 | 开启（但新用户需审核） | 陌生人可提交注册申请，别乱点通过 |
| 端口 19092 / 19093 | 监听所有网卡 | **API Key 泄露即可完全操控隧道与 DNS** |

::: danger 不要把 19092 / 19093 暴露到公网
这两个端口是给内网程序调用的。它们只能靠一个 Key 保护，且没有登录限速。用防火墙限制来源，或只在 VPN / 局域网内访问。
:::

## 公网暴露面板时

建议按顺序做这几件事：

### 1. 走 Cloudflare Access（最推荐）

在 Cloudflare Zero Trust 里给面板域名配一条 Access 策略（例如只允许你自己的邮箱），**访问前先过 Cloudflare 身份验证**。这样即便域名被扫描到，没有授权也进不来。这是比任何面板自带功能都强的防线。

### 2. 改站点名称与关掉开放注册

- 「系统配置 → 站点设置 → 站点名称」改成**不含业务特征**的名字，别用 `panel`、`tunnel`、`nas` 这类可被关键词命中的词
- 「用户管理 → 注册开关」**关闭**，禁止陌生人提交注册

### 3. 域名本身别太好猜

`panel.xxx.com`、`tunnel.xxx.com` 是扫描器的字典常客。用无规律的子域名能减少被批量扫描命中的概率。

### 4. 强密码 + 定期轮换 API 凭证

管理员密码不要复用，API 凭证定期删除重建。

## 三层反收录

「站点设置」里的「**禁止搜索引擎收录**」默认开启（**建议保持开启**），它会同时上三道拦截：

| 层次 | 内容 | 特点 |
|---|---|---|
| `GET /robots.txt` | `User-agent: *` + `Disallow: /` | 全站禁止抓取，守规矩的爬虫会直接离开 |
| `X-Robots-Tag` 响应头 | `noindex, nofollow, noarchive, nosnippet, noimageindex, notranslate` | 向爬虫声明不要索引或留快照；不能强制不守规则的爬虫遵守 |
| 页面 `<meta name="robots">` | 同样的 noindex 声明，另附 `referrer: no-referrer` | 从本页面点外链时不泄露来源地址 |

关掉这个开关后，`robots.txt` 会降级为只禁 `/api/`，响应头也不再发送。

::: warning 降低曝光 ≠ 访问控制
这三层只能**减少被搜索引擎和批量扫描器发现的机会**，挡不住已经知道你地址的人。真正防入侵请用 Cloudflare Access 或强密码。

另外：搜索引擎基本不会收录「没有任何外链指向」的地址。所以**不要在论坛、群聊、公开截图里贴出面板链接**，这一条比改名字更关键。
:::

## 凭据是怎么存的

桌面版数据在用户应用目录的 `data/`，Docker 默认在宿主机项目 `data/`。Cloudflare Token 当前保存在 `config.json`，不是系统密钥链加密存储；备份含敏感凭据，请限制访问并加密保存。调用 Cloudflare API 时会发送相应凭据和配置，业务流量经 Tunnel 经过 Cloudflare，不能宣传为所有数据永远不离开本机。

- Cloudflare API Token 只保存在**你自己的 `/data` 目录**（`config.json`）
- 用户密码用 **scrypt 加盐哈希**存储，不存明文
- 会话 Cookie 设了 `HttpOnly` + `SameSite=Strict`，有效期 7 天
- 项目不设置独立的遥测上报服务；管理 Cloudflare 隧道/DNS 的 API 请求仍会将相应凭据和配置发送给 Cloudflare，Git/npm/镜像下载也会访问配置的外部下载源。

## 如果凭据泄露了

1. 立刻去 Cloudflare 后台**删除那个 API Token**（新建一个填回面板）
2. 在「API 凭证」页删除所有可疑凭证
3. 检查隧道列表里的**转发规则有没有被改成陌生域名**
4. 检查 DNS 记录有没有被添加未知的 CNAME

## 一句话总结

| 场景 | 该做什么 |
|---|---|
| 只在内网用 | 保持默认即可，别把端口映射出去 |
| 想在外网访问面板 | 上 Cloudflare Access + 关开放注册 + 改站点名 |
| 只用隧道服务本身 | 面板端口别对公网开放，只开隧道用的域名 |
